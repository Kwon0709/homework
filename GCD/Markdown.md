# GCD알고리즘의 시간복잡도 및 Big-O분석 보고서
## 1. 알고리즘 개요

이 프로그램에서 GCD(최대공약수)를 구하기 위해 구현한 알고리즘은 **유클리드 호제법**이다.
```c
my_math find_Gcd(my_math a, my_math b) {
	while ( b!= 0) {
		int tmp = b;
		b = a % b;
		a = tmp;
	}
	return a;
}
```

이 알고리즘은 두 정수 a와 b에 대해,

b가 0이 될 때까지 a를 b로 나눈 나머지를 반복적으로 구하는 방식으로 최대공약수를 계산한다

---
## 2. 시간복잡도 분석

### 2.1 시간복잡도 정의
시간복잡도는 입력 크기에 따라 알고리즘이 수행되는 연산 횟수를 기반으로 추정한다.

### 2.2 핵심 연산
유클리드 호제법의 핵심 연산은 `a % b` (나머지 연산)이며, while 루프가 반복될 때마다 b의 값이 감소한다.

### 2.3 반복횟수분석
예시) a=18과 b=24를 입력 받음
---
| 단계 | a | b |
|------|---|---|
| 초기 | 18 | 24 |
| 1회 | 24 | 18 |
| 2회 | 18 | 6 |
| 3회 | 6 | 0 |

-> **종료:find_Gcd=6**

이처럼 반복이 진행될수록 b의 값은 계속 감소하며, 알고리즘은 빠르게 종료된다.

---
### 2.4 최악의 경우 분석
유클리드 호제법의 반복 횟수는 입력 값에 따라 달라지며,

최악의 경우는 두 수가 피보나치 수열을 이룰 때 발생한다.

이 경우 b의 값은 가장 느리게 감소하게 되며,

반복 횟수는 입력 크기 n에 대해 다음과 같이 표현할 수 있다.

n × (1/2)^k ≈ 1

이를 정리하면,
```
(1/2)^k = 1/n  
2^k = n  
k = log₂ n
```
즉, 반복 횟수 k는 log₂ n에 비례하게 된다.

또한 초기 입력에서 a와 b의 크기 관계(b > a 또는 b < a)는
전체 반복 횟수에 큰 영향을 주지 않는다.
---
## 3. Big-O 계산 및 표기

### 3.1 실행횟수
위의 분석 결과, 반복 횟수는 다음과 같이 나타난다.

k = log₂ n

### 3.2 Big-O 표기법
Big-O 표기법은 최고차항만 남기고 상수를 무시한다.

log₂n + 1 에서
- 상수 +1 제거
- 밑 2 제거 (로그 밑 변환 공식에 의해 밑은 상수로 취급되어 무시)

∴ **O(log n)**
---
## 4.결론
유클리드 호제법은 반복 횟수가 매우 적고,
입력 값이 증가하더라도 수행 시간은 로그(log n) 수준으로만 증가한다.

따라서 이 알고리즘은 매우 효율적인 방법으로,
큰 수의 최대공약수를 구하는 데에도 적합한 알고리즘이다.
